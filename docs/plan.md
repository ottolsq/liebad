## 当前里程碑

文件、接口、测试和执行顺序见 [编码实施计划](superpowers/plans/2026-11-23-liebad-implementation.md)。

交付可在本机运行的麦克风实时字幕原型。用户在置顶悬浮窗选择麦克风，点击「开始」后边说边看字幕，点击「停止」后可导出 UTF-8 `.txt`。

| 字幕会话 | 展示临时字幕，固定连续两轮一致的开头，按顺序保存定稿并处理停止收尾 | 已完成 |

| 识别引擎对比 | 用同一批中文与中英混说录音比较 Whisper 与 wav2vec 2.0 的首字延迟、改写次数和定稿错误率 | 已完成 |
| 识别引擎可选 | 悬浮窗提供「Whisper / wav2vec 2.0」选择，按所选引擎加载模型并跑完整会话 | 已完成 |

环境、依赖、模型、素材、耗时与待补项见[测试记录](test-records.md)。原型链路已跑通，基线模型定为 `faster-whisper-small`，简体输出用 `opencc` 后置转换；第 2 批把依赖固定到 `pyproject.toml`，包结构为 `src/liebad/`；第 3 批把采集与识别接进同一套协议，真实麦克风已验证；第 4 批把整条链路装进置顶悬浮窗，真实麦克风首字约 2.0 s，临时字幕用 `faster-whisper-base`、定稿用 `faster-whisper-small`；第 5 批接入进程回环，可用两个应用同时播放不同语音并只识别所选进程，关闭目标应用后提示重新选择音源；第 6 批加入 `tools/asr_bench.py`，wav2vec 2.0 首字更快（1.05–1.28 s vs 2.56–4.21 s）但定稿错误率更高（中文 0.400 vs 0.267，中英混说 0.778 vs 0.296）；按用户要求把两个引擎都做成界面可选项，wav2vec 2.0 在 worker 线程里按需加载并预热，首字计时改为从音频开始流动起算（实测 2.7 s）。

### 完成定义（DoD）

- [x] 用固定的识别结果验证稳定的字幕开头、停顿定稿，以及停止时最后一个语段恰好定稿一次（见[测试记录](test-records.md)第 2 批）。
- [x] 选中真实麦克风说一段连续的话，在语段结束前看到临时字幕。切换到其他前台窗口后，字幕栏仍显示在屏幕顶部。
- [x] 一句话说完后立即点击「停止」，用 UTF-8 打开导出的 `.txt`，逐段核对内容和顺序，确认最后一句完整且没有重复。
- [x] 将已验证的构建、测试和启动命令补入 README。

### 风险

| 风险 | 影响 | 应对 | 触发信号 |
|---|---|---|---|
| Windows Python 环境或依赖导入失败 | 原型无法启动 | 核对 x64 Python、虚拟环境和依赖版本，先跑通本地中文录音 | 解释器、依赖导入或识别探测命令返回错误 |
| 本机识别速度不足 | 不能在语段结束前稳定显示临时字幕 | 记录模型和音频窗口配置，使用同一录音复测并调整 | 首次字幕在语段结束后才出现，或连续输入时延迟持续增加 |
| 停止时仍有未定稿音频 | 导出的结尾可能漏字或重复 | 用固定结果覆盖停止收尾，再用真实麦克风和导出文件复核 | 说完后立即停止，导出中最后一句缺失、残缺或重复 |

### 验收方式

在本机用一段已知内容的中文录音验证引擎，再用真实麦克风验证开始、置顶显示、停止和导出。记录运行配置、首次出字时间及导出核对结果，在里程碑验收时汇报。
